# Практическая работа № 5 — Симулятор планирования CPU

Реализованы FCFS, SJF без вытеснения, SRTF, вытесняющий Priority и Round Robin.
Единая функция `simulate(processes, algorithm, **params)` возвращает интервалы
`(start, end, PID)`. Простой обозначен `IDLE`.

Вход: `PID arrival burst priority`. Время измеряется в условных целых тактах.
Меньшее число означает более высокий приоритет. При равенстве SRTF/Priority
сохраняется текущий процесс, затем учитываются прибытие и порядок во входе.
В RR новые процессы, включая прибывшие на границе кванта, добавляются до
повторной постановки вытесненного процесса.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 sched.py --algo rr --quantum 3 set1.txt
python3 sched.py --algo all set1.txt
python3 sched.py --algo priority --aging 5 starvation.txt
python3 experiments.py
python3 -m unittest -v
```

Для Ubuntu пакет `python3-venv` должен быть установлен.
Сам симулятор и тесты используют только стандартную библиотеку;
Matplotlib нужен для графиков.

## Метрики и проверка

Оборот = завершение − прибытие; ожидание = оборот − burst;
отклик = первый запуск − прибытие.
Загрузка CPU = занятые такты / время от 0 до последнего завершения × 100%.
Стоимость переключения равна нулю. Переключения считаются между соседними
интервалами разных процессов; переходы через IDLE и первый запуск исключены.

| Алгоритм на set1 | Среднее ожидание | Средний оборот |
|---|---:|---:|
| FCFS | 8,75 | 15,25 |
| SRTF | 6,50 | 13,00 |
| RR, q=3 | 13,50 | 20,00 |

`experiments.py` сравнивает алгоритмы на трех наборах и сохраняет CSV и PNG
в `results/`. Для RR исследуются кванты 1–10. Aging уменьшает числовой
приоритет на 1 за каждые 5 накопленных тактов ожидания; CPU-время в ожидание
не входит, накопленный бонус после запуска не сбрасывается.

Без aging процесс LOW начинает работу после 1600 тактов, с aging=5 — после 96.
Конечный набор показывает длительное ожидание; при бесконечном продолжении
того же высокоприоритетного потока без aging LOW вообще не получает CPU.

set1 содержит заданные arrival/burst и выбранные демонстрационные приоритеты.
set2, set3 и starvation — воспроизводимые демонстрационные данные:
в условии точные строки этих наборов не предоставлены. Пересоздание:
`python3 generate_data.py` (перезаписывает четыре входных файла).
Подробные результаты и выводы: [REPORT.md](REPORT.md).

Правильные ожидания: 0, 7, 10, 18; среднее — 8,75. Обороты: 8, 11, 19, 23;
среднее — 15,25. SRTF и RR полностью совпадают с эталоном задания.
